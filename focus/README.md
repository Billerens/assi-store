# Фокус

Таймер работы: на время сессии телефон уходит в «не беспокоить», сообщения копятся во Входящих,
отвлекающие приложения не открываются (или напоминают о себе), в конце — сводка пропущенного,
история по дням и циклы работа/отдых. Полное описание — `docs/modules/focus.md` в Axiko.

## Что включить на телефоне

- **Доступ к уведомлениям** — «Чувства телефона» в Axiko. Это способ A включения тишины (через
  службу уведомлений) и сводка без Входящих.
- **Доступ к режиму «Не беспокоить»** (необязательно): кнопка «Доступ к «не беспокоить»» на
  экране Фокуса открывает системный экран. Нужен для способа B, для уведомления, пробивающего тишину, и для канала
  будильника. Работает, только когда в манифесте Axiko есть `ACCESS_NOTIFICATION_POLICY` (правка
  оболочки); без неё Axiko в списке этого экрана нет.
- **Shizuku** (необязательно) — способ C: `cmd notification set_dnd`. Выключается настройкой
  «Пробовать через Shizuku».
- **Специальные возможности** («Экран» в «Чувствах телефона») — для отвлекающих приложений
  (событие `screen.app`). Без них блокировки нет, и экран говорит об этом до старта.
- **Доступ к статистике использования** (необязательно, правка `usage`) — досчитывает попытки
  открыть отвлекающее, если служба экрана была выключена.
- **Батарея → «Без ограничений»** для Axiko: точный конец сессии держится на будильнике оболочки,
  а Samsung может не разбудить «усыплённое» приложение — тогда тишина останется до запуска Axiko.
- **Модель** (необязательно): роль «Фокус: сводка» (`focus.digest`). Без неё сводка собирается
  из выжимок Входящих и правил. Режим разбора Входящих «без модели» Фокус тоже уважает.
- **Входящие** (необязательно): без них сводка — из уведомлений с запуска Axiko, а «пробивание
  сквозь тишину» Фокус делает сам по списку людей.
- **Диктофон** (необязательно): со сводкой сессии появляется кнопка «Надиктовать итог» — запись
  в Диктофоне с заголовком «Итог фокуса: <задача>» и тегами «фокус» и задача; сессия запоминает
  запись, и кнопка становится «Итог голосом» (открывает её). Без Диктофона кнопки нет.

## Как устроено

- `main.js` — сессия в `data/focus/state.json` (под замком; конец срабатывает один раз),
  тишина, точный конец (`job('focus:end', { once })`, без правки — `{ at: 'ЧЧ:ММ' }`, плюс поток
  со `sleep` для точности до секунды, пока жив процесс), восстановление при запуске (`start()` →
  `restore()`: прошедшая сессия заканчивается, идущая — снова встаёт на будильник), подписки на
  время сессии (`call`, `screen.app`, `notification` под ключом `focus`), сводка, запись в базу
  `focus` (таблица `sessions`) и в общую (`kind: 'focus'`, от 5 минут), циклы, очистка текстов
  сводок по `job('focus:clean')`. События для экранов: `focus.changed`, `focus.ended`,
  `focus.summary`.
- `logic/` — чистая логика под node: `timer` (время, продление, пауза, кольцо, восстановление),
  `dnd` (коды фильтров, когда включать и когда возвращать), `distract` (напоминание, вторая
  попытка пускает), `calls` (пропущенные, пауза/конец по звонку), `summary` (из Входящих или из
  уведомлений, заголовок, текст конца, запрос к модели), `history` (дни, неделя, задачи),
  `settings`.
- `android.js` — всё, что трогает Android: возможности оболочки, способы тишины по порядку
  (оболочка → A служба уведомлений → B `NotificationManager` → C Shizuku), постоянное
  уведомление с отсчётом и кнопками, уведомление конца, пробивающее уведомление, вибрация, кнопка
  «Домой», события использования, имя контакта.
- `tools/focus.js` — голосовой инструмент агента `focus`: `start`, `left`, `extend`, `end`,
  `missed`, `today`, `break`. При запуске модуль кладёт заглушку `tools/focus.js` в рабочую папку
  (свою не перезаписывает, чужой файл не трогает).
- Экран — три вкладки: «Фокус» (фишки длительности, задача, переключатели, кольцо; в конце —
  сводка с ответами на важное), «История» (14 дней, неделя, сессии), «Настройки». Сложенный
  телефон во время сессии — только кольцо, время и «Закончить»; разложенный — кольцо слева,
  цифры дня справа, сводка в две колонки; полураскрытый на столе — кольцо сверху, кнопки снизу.
- Тишина возвращается, только если её включил Фокус и фильтр сейчас тот, что он поставил.
  Если «не беспокоить» уже было включено или владелец сменил его посреди сессии — не трогает.
- Настройки — `data/focus/settings.json`, все числа на экране «Настройки»: длительности, режим
  тишины, строгость, отвлекающие приложения, люди «сквозь тишину», звонки, циклы, порог записи,
  сроки хранения, вибрация конца и другие.

## Правки оболочки

`store.json` → `shell`: `dnd`, `notify.actions`, `off`, `job.once`, `vibrate.pattern`, `usage`.
Каждая проверяется через `native('shell.features')`, без неё — запасной путь:

| Правка | Есть | Нет |
|---|---|---|
| `dnd` | `native('dnd.get' / 'dnd.set' / 'dnd.request')` | способы A, B, C из движка по порядку; фильтр — `getCurrentInterruptionFilter()` |
| `notify.actions` | `assi.notify` с кнопками, отсчётом, каналами `quiet` / `alarm` | своё `Notification.Builder` + приёмник в движке (пока жив процесс); свой канал с `setBypassDnd` |
| `off` | `off(name, 'focus')` | функция, которую вернул `on`, или пустой обработчик под тем же ключом |
| `job.once` | разовый точный будильник на конец | ежедневный `{ at: 'ЧЧ:ММ' }`, снимается в конце сессии |
| `vibrate.pattern` | узор вибрации из настроек | `VibrationEffect.createWaveform` |
| `usage` | досчёт попыток по `lib/usage` | только события `screen.app` |

## Для других модулей

`require('modules/focus/main.js')`:

- `status()` → `{ running, session, next, today, todayText, tasks, inbox, ways, canSilence,
  filter, features, last, settings, ... }`;
- `left()` → `{ running, kind, left, text }` («Фокус: ещё 18 минут · Отчёт»);
- `summary(sessionId)` → `{ session, headline, text, summary, missed, digest, dnd, ... }`
  (`null` вместо id — последняя сессия);
- `missed()` → `{ running, text, ... }` — что пришло за идущую сессию или за последнюю;
- `history()` → `{ days, sessions, today, week }`;
- `startFocus({ minutes, task, mode, dnd, block, cycles })`, `extend(minutes)`, `end(by)`,
  `startBreak(minutes)`, `next()`, `stopCycles()`;
- `dictate(sessionId)` → `{ ok, recordingId, screen }` или `{ ok: false, why }` — «Надиктовать
  итог»: `require('modules/recorder/main.js').startRecording({ title, tags, link: { module: 'focus',
  id } })`, id записи — в `sessions.recordingId`, в `summary()` — `session.recordingId` и `recorder`
  (стоит ли Диктофон: `assi.files.exists('modules/recorder/main.js')`);
- события `focus.changed`, `focus.ended`, `focus.summary`; в общей базе — `kind: 'focus'`.

## Проверки

- На компьютере: `node tests/timer.test.js`, `node tests/summary.test.js`.
- На телефоне: `module_check focus`. Все сессии проверок тестовые (`{ test: true }`): тишина не
  трогается, уведомлений и записей в общей базе нет. Проверка со Входящими подаёт подставное
  уведомление в их обработчик и удаляет беседу. Идущую настоящую сессию проверки не трогают
  (пропускаются), состояние и настройки возвращаются как были.

## Отступления от описания

- **Конец сразу после срока — «по таймеру», а не «после перезапуска».** Описание: при запуске, если
  `endAt` прошёл, — конец с `endedBy: 'restore'`. В коде (`logic/timer.js` → `restore()`, `main.js`
  → `restore()`): если срок прошёл не больше чем `restoreGraceSec` назад (настройка «Конец по
  таймеру, если приложение проснулось в течение, секунд», по умолчанию 120), конец пишется как
  `timer`. Причина: выгруженное приложение будит сам будильник конца сессии (`job('focus:end')`), и
  `start()` модуля успевает раньше задания — сессия кончилась вовремя, по таймеру, а в истории и
  общей базе стояло бы «после перезапуска». Настоящий перезапуск (приложение было мёртво дольше) —
  по-прежнему `restore`. Поставить настройку в 0 — будет ровно как в описании.

## Не сделано

- **Проверка на Fold5 по «Как проверить»** (п. 1–9 описания): тишина на 2 минуты и сообщение со
  второго телефона, что показывают «Настройки → Режимы» на One UI / Android 16, ручное «не
  беспокоить» до и посреди сессии, выгрузка Axiko и перезагрузка посреди сессии (точный будильник),
  отвлекающее приложение «строго», звонок с «закончить», сложенный / раскрытый / полураскрытый
  экран со снимками `scripts\shot.ps1`, путь C без запущенного Shizuku. Нужен настоящий
  телефон — по заданию adb и эмулятор не использовались. Логика каждого пункта проверена
  тестами и прогоном проверок в подобии движка под node.
- **Способ A: видит ли движок компаньон `NoticeService`**
  (`Packages.app.assi.sense.NoticeService.Companion.getInstance()`). Без правки `dnd` от этого
  зависит включение тишины без доступа к политике. Проверить можно только на телефоне.
- **Синтаксис `cmd notification set_dnd`** (путь C) на Android 16 / One UI 8: аргументы
  `priority`, `alarms`, `on`, `off` взяты из AOSP, не сверены с телефоном.
- **Режимы Android 15+ на One UI**: может ли стороннее приложение включать «не беспокоить» без
  подтверждения, не остаётся ли свой режим в списке после конца. Это главный риск модуля
  (раздел «Риски» описания).
- **Пробивающее уведомление и канал будильника**: `setBypassDnd` работает только с доступом к
  политике, а его нет без строки `ACCESS_NOTIFICATION_POLICY` в манифесте (правка оболочки, Axiko
  по заданию не менялся).
- **Свой режим через `AutomaticZenRule` с `ZenDeviceEffects`** (чёрно-белый экран на время
  фокуса) — в описании это «позже», правки оболочки нет; не делалось.
- **Полураскрытый Fold (Flex)**: вёрстка опирается на `vertical-viewport-segments` и
  `env(viewport-segment-*)` и на `navigator.devicePosture`; поддерживает ли их WebView на Fold5 —
  только на телефоне. Без них экран остаётся в обычной вёрстке.
- **Samsung «Режим фокусировки»** («Цифровое благополучие») — управлять им программно нельзя;
  оба режима могут работать одновременно.
- **Ограничения, оставленные намеренно**: вибрация и звук конца молчат, если «не беспокоить»
  включил сам владелец; сводка без Входящих — только из уведомлений с запуска Axiko (оболочка
  держит их в памяти); проверка экрана в `checks.js` выполняется только на телефоне.
