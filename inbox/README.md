# Входящие

Одна лента сообщений из всех мессенджеров, собранная из уведомлений: «Важно», «Подождёт», «Шум»,
выжимки болтливых групп, черновики и ответ прямо из ленты. Полное описание — `docs/modules/inbox.md`
в Axiko.

## Что включить на телефоне

- **Доступ к уведомлениям** — «Чувства телефона» в Axiko (или через Shizuku). Без него лента пуста,
  экран так и пишет.
- **Батарея → «Без ограничений»** для Axiko, иначе Samsung усыпит службу уведомлений.
- **Модели** (необязательно): роли «Входящие: разбор», «Входящие: выжимка групп», «Входящие:
  черновики ответов» в настройках моделей. Без моделей (или когда дневной лимит исчерпан) лента
  работает на правилах: коды, правила владельца, упоминания; всё остальное новое лежит в «Подождёт»
  с пометкой «не разобрано», и разбор догоняет его, когда модель снова доступна. Раскладывать без
  модели по простым признакам («Важно» / «Шум» наугад) — настройка «Без модели раскладывать
  простыми правилами», по умолчанию выключена; повтор важного и черновики сами срабатывают на такие
  догадки, только если она включена.
- **Где разбирать** — «авто» (по умолчанию): если на телефоне скачана модель, а ролям «Входящие:
  разбор» и «Входящие: выжимка групп» модель не назначена, модуль сам назначает им модель телефона
  (через провайдера с адресом `local:`; это видно в «Кто на какой модели»); иначе — облако.
  Черновики идут на модель своей роли.
- **Кто вы в чатах**: на экране «Настройки» → «Как меня называют» (имена и ники для упоминаний;
  при первом запуске подставляется имя из профиля владельца).

## Как устроено

- `main.js` — подписка `on('notification')`, разбор, склейка повторов и правок, корзины, выжимки,
  черновики, повтор важного, счётчик дня в `lib/base.js` (`kind: 'messages'`, `message_sent`),
  очистка `job('inbox:clean')`. Событие для экранов — `inbox.feed`.
- `logic/` — чистая логика под node: `parse` (разбор уведомлений по `parsers.json`), `dedup`
  (повтор / правка / новое), `triage` (правила и запрос к модели), `digest` (выжимки и черновики),
  `feed` (карточки, вкладки, виджет, сводка за период, поиск беседы по имени), `settings`, `sha1`.
- `android.js` — всё, что трогает Android: возможности оболочки, живое уведомление, открытие
  беседы, значки приложений, режим «Не беспокоить», своё уведомление «важного» с кнопкой ответа.
- `tools/inbox.js` — инструмент агента `inbox` (важное, беседа, поиск, сводка, черновик, отправка
  только с `confirmed: true`). При запуске модуль кладёт в рабочую папку заглушку `tools/inbox.js`,
  которая ссылается сюда (свою заглушку он не перезаписывает, чужой файл не трогает).
- Данные — `data/inbox/`: база `inbox` (таблицы `messages`, `chats`, `drafts`), `settings.json`,
  `parsers.json` (свои разборщики поверх заводских, по `id`), `state.json`, `icons/`.

## Правки оболочки

`store.json` → `shell`: `notice.full`, `notice.removed`, `notice.open`, `notify.actions`, `dnd`.
Каждая проверяется через `native('shell.features')`, без неё — запасной путь:

| Правка | Есть | Нет |
|---|---|---|
| `notice.full` | массив `messages`, `conversationTitle`, `isGroup` из события | те же поля из живого `StatusBarNotification` через экземпляр `NoticeService`; если не виден — заголовок и текст |
| `notice.removed` | событие `notification.removed`: прочитанное в мессенджере снимается со счётчика | беседа читается только в ленте |
| `notice.open` | `native('notices.open', key)` | запомненный `contentIntent`, затем запуск приложения |
| `notify.actions` | `axiko.notify` с кнопками «Ответить» / «Прочитано» | своё `Notification.Builder` + приёмник в движке (пока жив процесс) |
| `dnd` | `native('dnd.get')` | `NotificationManager.getCurrentInterruptionFilter()` |

## Для других модулей

`require('modules/inbox/main.js')`:

- `since(from, to)` → `{ from, to, total, chats, important[], others[], byBucket }` — для Фокуса;
- `repeatImportant({ until, people, everyMin, from })` / `repeatImportant(null)`;
- `draftFor(name, text, source, { notify, open, copy })` → `{ ok, found, chatId, draftId, ... }`;
- `find({ person, chat, text, since, until, bucket, limit })`, `cards()`, `feed(tab)`, `chat(id)`,
  `send(chatId, text, draftId)`, `widget()`.

## Проверки

- На компьютере: `node tests/parse.test.js`, `dedup`, `triage`, `feed`.
- На телефоне: `module_check inbox` — подставное уведомление проходит через обработчик модуля
  (`{ test: true, noModel: true }`: без модели, без уведомлений), созданные беседы удаляются.

## Отступления от описания

- **Правка сообщения узнаётся не только по времени.** Описание: тот же отправитель и чат, другой
  текст в течение 2 минут — правка. В коде ещё нужно, чтобы новый текст был похож на прежний
  (настройка `editSimilarity`, по умолчанию 0,5; окно — `editWindowSec`). Причина: уведомление
  MessagingStyle часто показывает только последнее сообщение, и два разных сообщения подряд за
  минуту («Привет» → «Ты где?») иначе склеились бы в одно «изменено», а первое потерялось бы.
  Поставить `editSimilarity` в 0 — будет ровно как в описании.
- **Правило владельца сильнее скрытого текста.** Если мессенджер скрыл текст, а беседа или человек
  под правилом «всегда важно» / «всегда шум», сообщение ложится в корзину правила (правило — про
  беседу и человека, текста ему не нужно), а не в «Подождёт». Показывается оно всё равно как
  «Текст скрыт приложением» — и в ленте, и в беседе, и в ответах инструмента. Без правила скрытое
  сообщение, как в описании, лежит в «Подождёт» (`bucket: 'hidden'`) и в модель не уходит.
- **Режим «авто» и роль с облачной моделью.** Описание: в «авто» разбор на модели телефона, если она
  скачана. Модуль не может сам выбрать модель для запроса — запрос идёт на модель роли. Поэтому роли
  без своей модели он назначает модель телефона, а облачную модель, которую владелец назначил роли
  сам, не перебивает: разбор идёт на ней. Кому нужно строго «только телефон» — режим «только модель
  на телефоне».
- **Настройка «Без модели раскладывать простыми правилами»** — сверх описания и выключена по
  умолчанию. Файл настроек, сохранённый до этой правки, мог запомнить её включённой — тогда её
  нужно выключить на экране «Настройки».

## Не сделано

- **Проверка на Fold5 по «Как проверить»** (п. 1–10 описания): три сообщения подряд со второго
  телефона, группы Telegram и WhatsApp, ответ из ленты, смахнутое уведомление, скрытый текст, SMS-код,
  правка, складывание, выгрузка из памяти, лимит 0,01 $. Нужен настоящий телефон и настоящие
  мессенджеры — по заданию adb и эмулятор не использовались.
- **Видит ли движок компаньон `NoticeService`** (`Packages.app.axiko.sense.NoticeService.Companion
  .getInstance()`) — от этого зависит запасной путь `MessagingStyle` и запуск `contentIntent` без
  правки `notice.full` / `notice.open`. Код есть, проверить можно только на телефоне.
- **Разборщики Viber, VK, MAX, Samsung и Google Messages, Signal** написаны по общим правилам
  этих приложений, но формат их уведомлений не сверен с настоящими — сверить и поправить в
  `data/inbox/parsers.json`.
- **Двойные мессенджеры (Dual Messenger)**: id беседы различает профиль (`#user`), но приходят ли
  уведомления второго профиля и работает ли ответ — только на телефоне.
- **Уведомление «важного» сквозь «Не беспокоить»** на Samsung (канал с `setBypassDnd`, канал
  `alarm` оболочки) — работает ли без доступа к политике DnD, проверить на телефоне.
- **`PendingIntent` после удаления уведомления** — действует ли ещё, проверить на телефоне.
- **`notification.removed`, `notices.open`, `notify.actions`** зависят от правок оболочки; пока их
  нет, работают запасные пути из таблицы выше.
- **Расход батареи локальной моделью** на разборе пачек — замерить на телефоне; при необходимости
  уменьшить «Пачку для локальной модели» в настройках.
